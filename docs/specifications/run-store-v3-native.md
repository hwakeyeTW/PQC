# Private five-producer Run Store (R2-S)

Contract `B04_PRODUCER_V3`, capacity profile `B04_V3_CAPACITY_R2`.
Authority: #57 AC-R2S-1--3 (comment 7203287718, dispatch 7203415130),
R2 capacity profile (comment 7201337475). This is a private synthetic/offline
storage contract, not a scanner, worker bridge, public reader or CLI selector.

## Trusted entry points and immutable reservation

`RunStore._begin_v3(run_id=..., expected_hosts=..., requested_flags=...,
limits=..., profile=..., producer_rules_raw=..., started_at=...)` selects V3
by trusted code only. There is no caller-selectable capacity or untrusted
marker-based dispatch. The old `begin`, `open`, `recover`, manifest 1.0.0
and V1/V2 validators retain their original behavior. `manifest_schema_v3()`
in `tools/run_store_v3.py` is the generator for the closed 1.1.0 schema.
Runtime validation additionally binds cross-document identities, limits,
references, times and exact bytes that cannot be expressed by JSON Schema.

Expected host records use derived RUN_SCOPED identities, literal target IDs,
no inventory authority, and the exact eight long-name boolean flags.
Nginx/TLS flags must be false. Requested producers and required details derive
from these flags, including an empty slot requirement for all-disabled hosts.
The original limits (1--10 hosts, forks 1--2, serial 2, SSH 15 s, command
30 s), baseline/extended profiles, Evidence 1.1.0, fixed synthetic bridge
source and batch manifest version 2 are preserved. `producer_rules_raw`
uses the original rule loader, <=64 KiB, frozen raw bytes/digest/version.
Both assessment and CFF are required; the caller cannot opt out.

The run has a sealed journal with `journal_version=1.1.0`, scope, sorted
intent IDs, exact `intent_times` mapping and nullable closed
`blocked_capacity_stage`. Reserve samples the local UTC clock independently
of the trusted actual start, which must not be later than reserve. No final
recorded/finished timestamp is pre-filled. `dispatch_intent(host_id)` writes
and syncs the intent before returning. It does not prove dispatch or a host
connection. Duplicate intents, host/flag drift and changed frozen rules are
rejected. The writer owns a pinned, exclusively locked local run directory.

`record_host(fragment, attempted=..., terminal=..., details=...)` accepts
one final host fragment, original terminal v2 row and a mapping from the six
closed slot names to exact canonical bytes. The fragment must have the same
source, start, expected host identity and no claims/findings. The original
terminal validator and actual `read_wire`, `normalize_handoff`, staged
receipts and companion/binding validators prove the projection and its
reference partitions. Wire and companion bytes must equal their canonical
serializers, including the original normalized SSH/Certificate companion
format. The fixed flags select all applicable staged producers; wire content
cannot select a different adapter. The full aggregate binder uses the same
binding semantics as the old binder with the private R2 raw validator. No
new collection IDs or acquisition results are generated by the Store.

Time is bound as start <= reserve <= intent <= observed <= known host finish
<= fragment recorded <= checkpoint recorded <= final recorded. Where a
terminal has no observation or no known host finish, no observation/finish is
invented. `checkpoint_recorded_at` is sampled by the writer before the
immutable checkpoint write. A later final finish is the actual batch finish,
not earlier than any known host finish or dispatch intent, and no later than
actual final recorded time. Test-only clock injection exercises synthetic
causality. Replay compares exact typed rows/identity/outcome, not the
normalizer's temporary run timestamps. Each 1.1.0 checkpoint seals the host
fragment, attempted flag, original final terminal, sorted details and
checkpoint recording time. The same writer can reuse its own validated
checkpoint only after reading the committed file and checking its exact seal
digest. A new open/recovery replays from actual bytes.

## Capacity and normal publication

All sizes are actual encoded bytes; MiB is 1048576 bytes. The admitted
per-host terminal/projection, raw/assessed registries, reference counts,
wire and CFF nodes/depth/string/array constraints remain those of the
original producer and R2-P validators. No generic public validator is
relaxed. The original IPC 3500-byte limit belongs to the unchanged worker
path; this slice performs no IPC or execution.

| Artifact | Fixed maximum |
|---|---:|
| producer-handoff-v2 | 1 MiB per host / 10 MiB run |
| platform-v2 | 1 MiB |
| certificate-assets-v1 | 2 MiB |
| openssl-runtime-v2 | 1 MiB |
| crypto-policy-v2 | 1 MiB |
| ssh-posture-v2 | 2 MiB |
| All detail slots per host | 8 MiB |
| Single host Evidence | 32 MiB |
| Full raw Evidence | 64 MiB |
| Full assessed Evidence | 96 MiB |
| CFF per-host entry / wrapper | 32 / 128 MiB |
| Sealed checkpoint / committed checkpoint total | 40 / 400 MiB |
| Core artifacts total | 256 MiB |
| Manifest / journal seal / prepared seal / terminal batch | 16 MiB each |
| Frozen, published producer rules and assessment rules | 64 KiB each |

Limits are conjunctive, not a promise that all independently maximal
inputs can coexist. The core includes raw, assessed, CFF, all present detail
slots, terminal bytes and both published copies of the frozen rules. The
checkpoint total is separate and includes actual seals. Accounting checks
before registry extend, before payload admission and before file reads;
actual serialized bytes and on-disk size are independently verified. The
original Store's private-key/secret-field checks apply; large R2-P derived
objects use the fixed private validators plus bounded secret walk, not the
old 32 MiB/4M structural JSON admission path. No file or directory name is
accepted from the caller.

`finalize(batch_raw=..., batch_rc=..., finished_at=...)` requires a durable
terminal checkpoint for every expected host (including all-disabled or
otherwise not attempted), and validates the full original terminal target
bijection and all frozen flags/outcomes. The raw aggregate is reconstructed
only from immutable checkpoint rows. Assessment is derived using the exact
frozen rules; CFF is the original R2-P global projection with one pair per
expected host and the full assessed Evidence digest, even for PARTIAL/ERROR.
Raw, assessed, terminal, all present details, both rules artifacts and CFF
are published with exact size/hash/reference metadata; missing required
slots on incomplete hosts are explicitly indexed with the retained terminal
reason available in the corresponding host row. A COMPLETE host cannot
omit required detail. `recovered_at` is null in normal publication.

The existing pinned-FD/owner/mode/device/nlink/local-FS/exclusive-lock and
no-replace primitives stage all core bytes, durably seal the immutable
1.1.0 prepared plan, move slots, reread exact final content, then publish the
single `run_manifest.json` commit marker last. An already published run
cannot be replaced or recovered in place. `_open_v3(run_id)` checks the
sealed reservation, plan, checkpoints, actual artifact index and every
artifact byte against the recomputed canonical result, including all
CFF/companion bytes, rather than trusting caller or indexed digests. No
new reader support is given to Portal/CBOM. The seals provide internal
consistency/corruption detection; they are not external signatures or a
sandbox against malicious same-UID code that can replace all trusted state.

## Capacity failure, interruption and recovery

`CapacityError` has the fixed code `V3_CAPACITY_LIMIT` and stage
`RAW_EVIDENCE`, `ASSESSED_EVIDENCE`, `CFF` or `CORE`. An aggregate failure
blocks the writer, writes the closed blocked stage only through the original
durable journal replacement, preserves committed checkpoints/terminals and
never publishes a false normal manifest or changes acquisition rc. A failed
journal write is not claimed durable. A per-host slot/checkpoint failure
rejects the new checkpoint without claiming that unsaved data survives.
There is no automatic retry, redispatch, data truncation or cap fallback.

`_recover_v3(run_id)` is explicit, exclusive and never reconnects. Without
a prepared plan, it reconstructs all expected hosts: committed terminals
remain unchanged, an intent without a terminal is ERROR/OUTCOME_UNKNOWN
with attempted null, and absent intent/checkpoint is NOT_ATTEMPTED. It
records actual recovery time as `recorded_at` and `recovered_at`, with
`finished_at=null`. It keeps producer rules and all committed detail bytes,
marks batch/assessment/rules/CFF as missing, and publishes the explicitly
incomplete recovery only if actual raw and core fit. Raw or core overflow
retains checkpoints and refuses publication. This is not normal finalize.

With a prepared plan, recovery validates the original version, stage,
manifest, timestamps, checkpoints, typed replay and artifact bytes, then
resumes the exact same plan. It does not turn a prepared normal publication
into an unprepared recovery or recompute its time. Unexpected, unsafe,
foreign, duplicate, missing or altered artifacts fail closed. Orphan stages
from interrupted pre-prepare writes stay private and bounded by the original
four-stage limit; no automatic deletion or overwrite is introduced.

## C4a explicit offline verification and recovery

`RunStore.open_v3(run_id)` explicitly selects manifest/journal 1.1.0 and
`B04_PRODUCER_V3` / `B04_V3_CAPACITY_R2` with the existing synthetic source.
`RunStore.recover_v3(run_id)` explicitly selects the corresponding recovery
path; `_open_v3` and `_recover_v3` delegate to the same implementations.
`open` and `recover` continue to reject V3; the V3 entry points do not fall
back to 1.0.0. No new CLI, scan, producer registration or derived publication
is enabled. `PublishedRun` is a verified snapshot of manifest, document,
assessed document and exact fixed-slot bytes, not a capability token. A
caller must not turn a constructed or mutated snapshot into file authority.

The V3 reader holds the existing shared per-run lock and checks the retained
root FD identity plus the pinned run and lock identities against their
non-follow names relative to the pinned root/run after acquiring the lock
and before delivering a result. It does not reopen the original caller root
path. A renamed root remains the pinned authority; a replaced root FD or a
replaced/detached run or lock is rejected. The active prepared stage is
pinned and rechecked. Canonical sealed journal/plan, frozen rules, terminal
checkpoint replay, fixed artifact index, size/hash/bytes and capacities
remain the publication authority. Reading does not write or refresh anything.
The core namespace stays closed: no stable HTML/CSS, portal generation,
foreign core or arbitrary detail slot. Existing bounded abandoned stages and
private temps are not adopted, traversed or automatically removed; unsafe
metadata is rejected.

Explicit recovery holds the exclusive lock, rejects any pre-existing marker,
and checks the unprepared namespace before staging. It preserves the existing
prepared plan and exact core bytes, or derives the original unprepared
recovery outcome from existing frozen rules, intents and terminal checkpoints.
An intent without terminal is UNKNOWN; no intent is NOT_ATTEMPTED. Missing
batch, assessed/CFF and assessment rules artifacts remain explicitly absent.
No scan, reconnection, re-assessment of an interrupted acquisition, automatic
retry or cleanup of abandoned material occurs. Before recovery writes and at
the final marker switch the pinned identities are rechecked. After the marker
temp is durable and before no-replace publication, the original sealed plan,
frozen journal/rules, checkpoint set/digests and exact final core are verified
again, without generating another assessment/CFF. A failed post-publication
sync is DURABILITY_UNCONFIRMED, not a rollback or a success; use explicit
`open_v3` for subsequent verification. Existing size and slot ceilings remain
unchanged. The Catalog's `--recover` is unrelated to run recovery.

These guarantees assume cooperating trusted local UID/administrator and the
existing local POSIX filesystem contract, not an adversarial same-UID sandbox
or a physical power-loss guarantee. Actual Controller/Oracle Linux, storage
and formal release verification remain #28. C4b is a separate derived
consumer/publication contract.
